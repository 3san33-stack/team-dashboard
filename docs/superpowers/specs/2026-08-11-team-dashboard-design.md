# 팀 업무관리 대시보드 — 설계 문서

## 배경 / 목적
디자인R&D 팀의 개인별 업무관리 엑셀 시트(`디자인R&D_업무관리_개인시트.xlsx`)를 웹 대시보드로 대체한다.
팀원 5명(이은혜, 김혜진, 양세현, 구민석, 안도현)이 각자 컴퓨터에서 접속해 업무를 등록/수정하고,
팀 전체 현황을 한눈에 볼 수 있어야 한다. 로그인 없이 웹에서 바로 쓸 수 있어야 하고(웹 전용),
디자인은 Linear를 베이스로 하되 애니메이션/모션이 더 적극적으로 들어간 "전문가적이면서 역동적인" 느낌이어야 한다.

기존에 만든 `todo-dashboard`(개인용, localStorage 기반)와는 별개의 새 프로젝트다.

## 기술 스택
- **Next.js (App Router)** — 웹 전용
- **Supabase** — Postgres DB + JS 클라이언트. 팀 전체가 같은 데이터를 실시간 공유
- **shadcn/ui** — 기본 UI 컴포넌트 (버튼, 인풋, 셀렉트, 다이얼로그, 뱃지, 테이블)
- **bklit-ui** — 진행률 게이지/차트 (필요한 범위 내에서)
- **motion** (framer-motion 계열, bklit-ui도 내부적으로 사용 중) — 카운트업, 스태거 등장, 스프링 진행률 바, 호버 트랜지션

## 인증 / 접근
- 비밀번호 없음. 첫 진입 시 "나는 누구인가" 이름 선택(5명 중 택1) → 로컬(브라우저)에 저장해 다음 방문 때 기억
- 이 선택은 "누가 작성/수정했는지" 표시 용도일 뿐, 보안 경계가 아님 (내부 소규모 팀 용도로 허용된 트레이드오프)
- Supabase는 anon key + 공개 read/write RLS 정책 사용 (내부용, 낮은 민감도 데이터 전제)

## 데이터 모델 (Supabase `tasks` 테이블)
```sql
create table tasks (
  id uuid primary key default gen_random_uuid(),
  member text not null,              -- '이은혜' | '김혜진' | '양세현' | '구민석' | '안도현'
  project text not null,             -- 프로젝트명
  category text not null,            -- '제품개발' | '타부서(팀)지원' | '조직연구' | '샘플제직' | '생산지원' | '기타업무' | 'OKR'
  detail text,                       -- 세부업무
  priority text not null default 'P3-보통',  -- 'P1-긴급' | 'P2-높음' | 'P3-보통' | 'P4-낮음'
  start_date date,
  due_date date,
  progress int not null default 0,   -- 0~100
  status text not null default '예정', -- '예정' | '진행중' | '검토중' | '완료' | '보류'
  comment text,                      -- 팀장코멘트
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now()
);
```
"지연"은 컬럼이 아니라 화면에서 `due_date < 오늘 AND status != '완료'`로 계산한다.

## 화면 구성 (1차 범위)

### 1. 이름 선택 (최초 1회)
5명 중 하나를 선택하는 카드형 선택 화면. 선택 후 로컬스토리지에 저장, 다음부터는 스킵.

### 2. 상단 요약 카드 (4개)
전체 업무 / 진행중 / 완료 / 지연 개수. 페이지 진입 시 0에서 실제 값까지 숫자가 카운트업되는 애니메이션.

### 3. 팀원별 진행률 바 (5개, 스태거 등장)
각 팀원의 평균 진행률(해당 팀원 업무들의 progress 평균)을 가로 바 형태로. 페이지 로드 시 왼쪽에서
스프링 애니메이션으로 채워짐. 카드 순서대로 약간의 딜레이를 두고 순차 등장(stagger).

### 4. 업무 목록 + CRUD
- 테이블/카드 리스트로 전체 업무 표시 (담당자, 프로젝트, 업무구분, 우선순위, 마감일, 진행률, 상태)
- "업무 추가" 버튼 → 다이얼로그 폼 (담당자는 현재 선택된 이름이 기본값, 변경 가능)
- 각 행에서 수정/삭제 가능
- 상태별 색상 뱃지 (예정=회색, 진행중=파랑, 검토중=보라, 완료=초록, 보류=주황)
- 우선순위 뱃지 (P1=빨강 강조 ~ P4=연한 회색)
- 지연된 업무는 마감일이 빨간색으로 강조

### 5. 필터
담당자별 / 상태별 드롭다운 필터. 필터 변경 시 목록이 부드럽게 리레이아웃(모션).

## 디자인 톤
Linear를 베이스로 하되 모션을 더 적극적으로:
- 다크 톤 배경, 여백 넉넉한 카드, 은은한 그림자와 얇은 보더
- 페이지 진입 시 카드들이 순차적으로 살짝 아래에서 위로 페이드인 (stagger)
- 숫자는 카운트업, 진행률 바는 스프링 이징으로 채워짐
- 카드 호버 시 살짝 떠오르는(translateY + shadow 증가) 효과
- 필터/상태 변경 시 레이아웃이 튀지 않고 부드럽게 전환

## 에러 처리
- Supabase 연결 실패 시 화면에 재시도 버튼과 함께 에러 메시지 표시 (빈 화면으로 죽지 않음)
- 업무 저장 실패 시 토스트로 에러 알림, 입력값 유지

## 스코프에서 제외 (YAGNI, 다음 단계)
- 월간 담당자별 기여율 차트, 부서장님 보고 요약, 8월 업무 캘린더 — 시트에는 있지만 1차 범위 아님
- 엑셀 업로드/가져오기 — 데이터는 웹에서 직접 입력하는 것으로 대체하므로 불필요
- 비밀번호 기반 인증 — 내부 소규모 팀, 이름 선택으로 충분
- 실시간 협업 커서/누가 지금 보고 있는지 표시 — 요구사항 아님

## 테스트
- 지연 여부 계산 함수 단위 테스트 (마감일 지남+미완료 → true, 완료 → false, 마감일 미래 → false)
- 팀원별 평균 진행률 계산 함수 단위 테스트 (업무 0건일 때 0%, 여러 건 평균)
- 상태/우선순위 뱃지 색상 매핑 테스트
